# 里程碑执行计划

> 状态：v1.0 · 2026-10-30  
> 关联：[路线图](ROADMAP.md) · [架构](ARCHITECTURE.md) · [状态](specs/state.md) · [权限](specs/permission.md) · [主题](specs/theme.md)

这份文档把路线图里的 M0–M5 展开成可执行的范围、非目标、验收和架构门槛。**战略取舍看 [ROADMAP.md](ROADMAP.md)，技术契约看 `specs/`，具体任务进 GitHub Issues。**

时间盒按“单人每周 10–15 小时”估算，是相对时间，不是承诺日期。

| 阶段 | 时间盒 | 要解决的问题 | 结果（outcome） | 通过门槛 / kill criteria |
|---|---|---|---|---|
| **M0 验证** | 1 周 | 最大的技术/需求不确定性 | 权限 hook 可行性、事件清单、10 人访谈、安装失败基线 | 权限可行/不可行有结论；多开比例、top pain 有数据 |
| **M1 核心 loop** | 2 周 | 不错过、不消失、不折腾 | 生命周期修复、单实例、8 事件、原生通知、doctor、隐私模式 | 24h dogfood 无 missed needs-input；崩溃可恢复 |
| **M2 权限注意力** | 2 周 | 少切窗口 | 通知 + 点击聚焦；spike 通过后加单请求卡片 | 80% 权限事件 30s 内被看到；零误放行；p95 < 200ms |
| **M3 多会话** | 1–2 周 | 多开不乱 | 计数 + 最高优先级 + 菜单列表 | 3 会话不闪烁；单开不退化；多开用户可用 |
| **M4 陪伴/个性化** | 2 周 | 愿意常开 | 待机动画、状态过渡、首启引导、本地主题导入 | 7 日开启率提升；无打扰投诉；主题导入可用 |
| **M5 分发** | 2 周 | 装得上 | 一键脚本/zip、macOS 托盘、英文 README、demo | 安装成功率 > 90%；无需读 Python 文档 |

## M0 验证与去风险（1 周）

**要回答的问题**

- Claude Code 当前版本到底暴露哪些 hook 事件？插件引擎和原生 hooks 各能拿到什么？
- `PermissionRequest` 能不能阻塞并返回 allow/deny？失败/超时会不会阻塞终端？
- 用户最痛的是“错过权限”“多开混乱”还是“安装失败”？
- 多会话用户占比多少？值得为它做一套聚合 UI 吗？
- 安装失败主要发生在哪一步：Python、venv、PyPI、权限、启动？

**交付物**

- `docs/adr/0001-permission-hook.md`：go / no-go 结论、测试矩阵、失败路径。
- `docs/research/evidence.md`：10 人访谈摘要、issue 挖掘、安装失败分类。
- 基线指标：Release 下载、issue 类型、setup 失败日志（用户主动提供）。
- 一份按 M1/M2 拆好的 GitHub Issues。

**明确不做**

- 不写权限卡片 UI。
- 不引入新运行时/打包工具。
- 不改状态协议；先记录现状。

**Go / No-go**

- 权限 hook 不可靠 → M2 只做通知 + 聚焦，关闭卡片分支。
- 多开 < 20% → M3 降级为 Later，不投入聚合 UI。
- 一键脚本安装成功率 > 95% → 签名/公证继续后置。

**架构动作**

- 建 `docs/adr/`；记录 spike 决策。
- 不写生产功能代码；spike 脚本放 `spikes/`，不合并到主分支。

## M1 核心 loop（2 周）

**结果**

单会话、崩溃、重启都可靠；不需要盯终端也不会错过“轮到你”。

**范围**

- 生命周期修复：不再用 `tasklist claude.exe` / `pgrep claude` 决定退出；改为“活跃会话 + 状态 TTL”。
- 单实例：锁文件 + PID + 端口；端口被占用时明确提示，不静默退出。
- 8 个核心事件映射（见 [状态协议](specs/state.md)）；新状态必须配新动画/文案才允许加。
- 原生通知：macOS `UNUserNotificationCenter`（或 `osascript` 兜底）+ Dock 弹跳；Windows Toast + 任务栏闪烁。
- 点击通知 → 聚焦对应终端/窗口；失败时显示项目路径。
- `/pet doctor`：版本、平台、Python/依赖、状态目录权限、最近状态文件、hooks、日志路径；输出可复制文本。
- 隐私模式：隐藏项目名/文件名；状态文件不写 prompt/完整命令。
- 状态文件原子写 + 损坏容忍；旧格式兼容。
- 基础测试 + CI（lint/type/unit；macOS/Windows 冒烟）。

**不做**

- 权限卡片、全局热键、审批队列。
- 多会话聚合 UI（只保证不崩、不误读）。
- 主题、XP、看板。

**通过门槛**

- 24 小时 dogfood：没有“需要我但没看到”的事件。
- 杀掉 pet 进程，下一次 Claude 事件后自动重启；`/pet` 也能手动拉起。
- Windows 终端里跑 Claude Code，桌宠不会因为找不到 `claude.exe` 而退出。
- `/pet doctor` 能定位：venv 缺失、端口被占、状态目录不可写、hooks 未生效。
- CI 在 macOS 和 Windows 上通过。

**架构门槛**

- 抽出 `pet/core/` 的 state reader、session aggregator、view model；`pet_mac.py` / `pet.pyw` 变薄。
- 重构与功能分开 PR；行为不变，测试先绿。
- 详见 [ARCHITECTURE.md](ARCHITECTURE.md) §6 步骤 1–2。

## M2 权限注意力（2 周，条件启动）

**结果**

权限请求不再悄悄卡住；用户能在不切窗口的情况下看到并处理大部分请求。

### 阶段 1（默认交付）

- `PermissionRequest` / `Notification` → `attention` 状态 + 原生通知 + 声音 + 菜单“去处理”。
- 点击通知/菜单 → 聚焦终端；不能聚焦时显示项目路径和提示。
- 同一会话/工具的重复请求 2 秒内去重。
- 勿扰模式：只保留气泡/角标，不弹横幅、不响铃。

### 阶段 2（仅当 M0 spike 通过）

- 单请求卡片：工具名、项目、摘要、风险徽标、展开完整命令、Allow / Deny / 回退终端。
- 本地 HTTP bridge；超时/异常/宠物挂掉 → `ask`，回退终端。
- 高风险命令：默认焦点在“回退终端”，禁用全局快捷键，二次确认。
- **不做**：审批队列、全局热键、审计日志默认开启、远程审批、自动 allow。

**通过门槛**

- 连续触发 5 个权限请求，不丢、不卡死；忙时直接回退终端，不排队。
- 手动杀掉 pet，再触发权限请求，终端正常弹出原生提示，不被阻塞。
- 含 `rm -rf` 的命令显示“破坏性操作”警告。
- 审批 p95 < 200ms；宠物挂掉/桥接失败时，工具调用耗时不超过原生提示的 1.2 倍。
- 测试中零误放行。

**Kill criteria**

- spike 失败、hook 行为不稳定，或出现任何误放行 → 只发阶段 1，关闭阶段 2。
- 卡片让用户更困惑/更慢 → 回到“通知 + 聚焦”，不做审批 UI。

**架构门槛**

- bridge 独立模块，不在 renderer 里；renderer 不做网络。
- 权限客户端只负责传输，不负责 UI 决策。
- 契约测试覆盖 bridge 鉴权、超时、忙时、非法 JSON、宠物挂掉。
- 详见 [权限 spec](specs/permission.md) 和 [ARCHITECTURE.md](ARCHITECTURE.md) §6 步骤 4。

## M3 多会话（1–2 周，条件启动）

**结果**

同时开 2–5 个会话时，知道谁在干活、谁卡住、谁完成，不闪烁。

**范围**

- 扫描 `sessions/*.json`，过滤过期/损坏文件。
- 优先级：`attention > error > waiting > celebrate > tool/reading > thinking > idle`。
- 同优先级按 `ts` 倒序；再相同按 `session id` 保证确定性。
- 气泡：主会话文案 + ` · N 个会话`；有需要处理的再加 ` · M 个等你`。
- 右键菜单：项目、状态、已运行时长；点击切换主会话。
- 不做：锁定会话、逐会话聚焦、复杂 tie-break、会话历史。

**通过门槛**

- 一个 working、一个 waiting、一个 error：气泡显示“3 个会话 · 2 个需要你”，不闪烁。
- 单会话体验不退化。
- 损坏/过期文件不影响主流程。

**Kill criteria**

- M0 数据显示多开 < 20% → 降级为 Later，只保留“不崩、不误读”。

**架构门槛**

- 聚合器是纯函数；用 fixture 测优先级和 TTL。
- view model 与渲染分离；平台层只负责画和菜单。

## M4 陪伴与个性化（2 周）

**结果**

用户愿意长期开着，而不是装完看一次。

**范围**

- 待机动画、状态过渡、随机台词、首次启动引导。
- 本地 Petdex 导入：`/pet theme install <path>`、`/pet theme use <id>`、`/pet theme list`、`/pet theme remove <id>`。
- 设置：勿扰、减少动态、点击穿透、自动隐藏、多屏位置；键盘操作、屏幕阅读器标签、高对比。
- 可选：按项目显示不同宠物（先不做，等主题格式稳定）。

**不做**

- 自建画廊/API、主题商店、XP 联动、付费主题。
- XP/等级/成就（Explore，不在 M4 主线）。

**通过门槛**

- 导入一个 Petdex 包并切换成功；缺状态按 spec 回退，不崩溃。
- 主题包校验：尺寸、帧数、许可证、路径穿越、超大文件。
- 7 日开启率有提升；没有“太吵/挡代码”的集中投诉。

**架构门槛**

- theme loader 在 feature 模块，不进入 core；core 不认识主题。
- 主题只允许 JSON + 图片 + 音频，不执行代码。
- 详见 [主题 spec](specs/theme.md)。

## M5 分发（2 周）

**结果**

新用户不用读“Python 环境考试”就能用上。

**范围**

- 一键安装脚本/zip（macOS/Windows），带卸载。
- macOS 菜单栏/托盘：状态点、会话数、显示/隐藏、勿扰、退出。
- 英文 README 首屏；中文 README 保留。
- demo GIF/短视频；插件市场文案；中文社区/awesome list 投放。
- 安装失败日志分类；`/pet doctor` 增加“复制诊断信息”。
- 打包 spike（PyInstaller）只做可行性验证，不承诺本阶段发布 `.app`/`.exe`。

**通过门槛**

- 干净机器（已有 Python）2 分钟内完成安装并看到桌宠。
- 安装成功率 > 90%；失败能定位到具体步骤。
- 卸载后不残留 hooks/进程/开机启动项。
- 英文用户能按 README 完成安装。

**Kill criteria**

- 一键脚本成功率 > 95% → 签名/公证/安装包继续后置，不为了“看起来专业”烧时间。

**架构门槛**

- runtime resolver 独立：打包 app > 插件 venv > 系统 Python；启动逻辑不散落在 hooks 里。
- 安装/卸载幂等；先备份再改 `settings.json`。

## v1.0 稳定化（M5 之后 1–2 周）

- 功能冻结，只修 bug。
- QA 矩阵：macOS 11/14/15（arm/intel）、Windows 10/11、多显示器、DPI 125%/150%、睡眠唤醒、锁屏、深浅色、中英文。
- 性能剖析、日志轮转/脱敏、隐私审查、迁移测试。
- 文档：README、安装、排错、隐私、贡献、架构。
- 发布清单：版本号、CHANGELOG、tag、CI artifact、marketplace 更新、回滚方案。

**通过门槛**

- 2 周无 P0/P1 未解决 bug。
- 干净安装成功率 > 95%（手动矩阵）。
- 权限流程 p95 < 200ms；宠物挂掉不阻塞。
- 3 会话并发不闪烁、不丢状态。
- 主题导入/切换/回退稳定。
- 中英文文案完整；无未翻译硬编码。
- 卸载干净；升级不丢设置。
- Explore 项（XP/看板等）不作为 v1.0 门槛；如果已进入主线，再单独加验收。
