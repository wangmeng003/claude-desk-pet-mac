# Claude Desk Pet 路线图

> 状态：lean v2.0 · 最后更新：2026-10-30  
> 适用版本：v0.1.3 起  
> 关联文档：[架构约定](ARCHITECTURE.md) · [状态协议](specs/state.md) · [权限](specs/permission.md) · [主题](specs/theme.md) · [竞品调研](research/competitive-landscape.md)

**怎么用这份文档**

- 路线图只回答三个问题：**先做什么、为什么、什么算完成**。
- 技术细节放 `docs/specs/`；具体任务转成 GitHub Issues；架构或契约变更先写 ADR。

## 0. 一页结论

**产品定义**：Claude Code 的轻量桌面注意力层。不是另一个 Agent 工作台。

核心 loop：

```text
Claude 事件 → 桌宠状态 → 需要我吗？
     ↑                        ↓
     └──── 我处理完 ←── 通知 / 声音 / 悬浮窗
```

用户雇佣它只做三件事：

1. **我不用盯终端，也知道 Claude 在干嘛。**
2. **Claude 需要我时，别让我错过。**
3. **它别挡我、别烦我、装起来别折腾。**

“可爱”是让这三件事愿意被长期使用的包装，不是独立 KPI。主题、XP、看板、工作台、20+ Agent 都是核心 loop 成立之后的放大器。

**成功指标**：missed needs-input rate、time-to-acknowledge、7 日仍开启比例、安装成功率。不是 stars、功能数或 Agent 数量。

**范围**

| 层级 | 内容 |
|---|---|
| **Now（5 周）** | M0 验证 → M1 核心 loop → M2 权限注意力 |
| **Next（条件启动）** | M3 多会话 → M4 陪伴/个性化 → M5 分发 |
| **Later** | v1.0 稳定化；v1.x 适配器/远程通知 |
| **Explore（有触发条件再做）** | XP/成就、用量看板、远程通知、硬件桥、20+ Agent、工作台、规则引擎、插件 SDK、自动更新、签名/公证、匿名指标 |
| **暂缓** | LLM 行为拦截（唯一明确不做的方向，见 §9） |

> Explore 不是“不做”，而是“有证据再做”。触发条件满足后直接进入 Next，不需要重新讨论是否允许做。

## 1. 问题与判断

### 1.1 用户雇佣它做什么

| 用户任务 | 现在的痛点 | 我们的答案 |
|---|---|---|
| 知道 Claude 在干嘛 | 长任务跑起来后只能盯终端；多开时不知道谁在干活 | 一眼可见的状态 + 项目名 + 气泡文案 |
| 不错过需要输入 | 离开终端，回来发现卡在 allow 三分钟 | 原生通知 + 点击聚焦；权限卡片只在 spike 通过后做 |
| 不被挡住/不被打扰 | 悬浮窗挡代码、分心、全屏时突兀 | 自动隐藏、点击穿透、勿扰、减少动态、安静默认 |
| 装得上 | macOS 首次运行要建 venv、从 PyPI 装依赖 | 一键脚本/打包；签名后置到有证据时 |
| 有点个性 | 想要自己的宠物/立绘 | 先做本地 Petdex 导入；不自建画廊 |

### 1.2 差异化

- **最轻**：Claude Code 插件市场一键装，核心不引入 Electron/Node 常驻运行时。
- **原生**：macOS 用 `NSWindow`，Windows 用 Tk，保持低资源占用。
- **中文优先**：中文文案、中文文档、中文社区反馈。
- **Claude Code 深度**：先把 hooks、权限、Token 做透，再扩其他 Agent。
- **桌宠 + 工具**：可爱是入口，省时间才是留存理由。

### 1.3 现在不做什么

| 不做 | 原因 | 什么时候重新考虑 |
|---|---|---|
| Electron 工作台 | 核心 loop 还没做扎实；工作台是第二产品 | 核心 7 日留存稳定 + 明确需求（v2 Explore） |
| 20+ Agent | 单人维护不了；先做 3–5 个官方适配 | 3–5 个适配器稳定后，由社区扩展 |
| 自建主题画廊 | Petdex 已占格式/画廊；重复造内容平台 | 本地导入率 > 5% 且有创作者主动投稿 |
| 默认遥测 | 信任成本高；先用访谈/issue/本地诊断 | 有明确指标缺口，且 opt-in 方案通过隐私审查 |
| LLM 行为拦截 | 误报、信任、延迟、责任 | 见 §9 的重新评估条件 |

## 2. 产品原则

1. **注意力优先**：每个功能都要回答“能不能减少一次切窗口/一次回来发现卡住”。
2. **轻量**：核心不引入 Electron/Node 常驻运行时；控制中心是可选组件。
3. **Fail-open**：桌宠、bridge、主题、通知任何一环挂掉，都不能阻塞 Claude 的工具调用或权限流程。
4. **本地优先**：默认不联网；主题下载、远程通知、匿名指标都必须显式开启。
5. **安静默认**：默认低调；自动隐藏、点击穿透、勿扰、减少动态是基础能力，不是高级设置。
6. **可选游戏化**：等级/成就/连续天数可关闭；饥饿/惩罚/内疚式提醒默认不做。
7. **双平台同协议**：macOS/Windows 共用状态协议和核心逻辑；渲染层分开。
8. **可诊断/可回滚**：每个失败都能在 `/pet doctor` 和日志里定位；升级前备份设置和状态。
9. **架构先行**：新功能必须落到明确的模块边界；边界不清时先重构或写 ADR，不在 god object 上继续加功能。
10. **可访问性**：减少动态、键盘可操作、屏幕阅读器标签、高对比、勿扰/暂停；悬浮窗必须能“完全不打扰”。

## 3. 里程碑

详细范围、非目标、验收和架构门槛见 [MILESTONES.md](MILESTONES.md)。这里只保留决策视图。

| 阶段 | 时间盒 | 要解决的问题 | 结果（outcome） | 通过门槛 / kill criteria |
|---|---|---|---|---|
| **M0 验证** | 1 周 | 最大的技术/需求不确定性 | 权限 hook 可行性、事件清单、10 人访谈、安装失败基线 | 权限可行/不可行有结论；多开比例、top pain 有数据 |
| **M1 核心 loop** | 2 周 | 不错过、不消失、不折腾 | 生命周期修复、单实例、8 事件、原生通知、doctor、隐私模式 | 24h dogfood 无 missed needs-input；崩溃可恢复 |
| **M2 权限注意力** | 2 周 | 少切窗口 | 通知 + 点击聚焦；spike 通过后加单请求卡片 | 80% 权限事件 30s 内被看到；零误放行；p95 < 200ms |
| **M3 多会话** | 1–2 周 | 多开不乱 | 计数 + 最高优先级 + 菜单列表 | 3 会话不闪烁；单开不退化；多开用户可用 |
| **M4 陪伴/个性化** | 2 周 | 愿意常开 | 待机动画、状态过渡、首启引导、本地主题导入 | 7 日开启率提升；无打扰投诉；主题导入可用 |
| **M5 分发** | 2 周 | 装得上 | 一键脚本/zip、macOS 托盘、英文 README、demo | 安装成功率 > 90%；无需读 Python 文档 |

> 如果只有 4 周：**做 M0 + M1，M2 只做 P1 通知/聚焦**，不做审批卡片。这比铺满功能更可能做出有人每天开的东西。

**共同规则**

- 每个阶段开始前冻结范围；结束后做一次 go / no-go，不自动滚入下一阶段。
- 重构与功能分开 PR；行为不变，测试先绿。
- 每个阶段至少产出一个可发布版本；不把 6 个阶段攒成一次大发布。
- 架构门槛不通过，功能不算完成；见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 4. Later / Explore

Explore 项不排期，但写清“为什么可能做、什么信号触发、第一步做什么”。触发后直接进入 Next。

| 方向 | 为什么可能值得做 | 触发条件 | 第一步 | 维护成本 |
|---|---|---|---|---|
| XP/等级/成就 | Token 是天然经验值，可能提升留存 | 7 日留存低于目标，且 ≥10 个用户主动要 | opt-in 实验：只显示等级，不做惩罚 | 低 |
| 用量看板 | 用户想看 7/30 天趋势和成本 | `/token-stats` 不够用，或 ≥10 个明确请求 | 先接 `ccusage`/本地 JSONL，生成 HTML | 中 |
| 远程通知 | 长任务离开电脑时仍想收到审批/完成 | 多用户反馈“不在电脑前” | Telegram/飞书 webhook，只发摘要 | 中高（安全） |
| 硬件桥 | 第二屏/桌面硬件宠物 | 有硬件用户/合作方 | HTTP/WebSocket 状态推送；BLE 只做 spike | 中 |
| 3–5 个 Agent 适配 | 用户同时用 Codex/Gemini/Cursor | ≥20% 用户使用非 Claude Agent | 定义 adapter contract + 2 个官方适配 | 中 |
| 20+ Agent/社区 registry | 扩展生态 | 3–5 个适配器稳定且有社区维护者 | 兼容矩阵 + 契约测试 + 社区标签 | 高 |
| 工作台/控制中心 | 会话历史、权限队列、用量分析 | 核心留存稳定 + 明确需求 | Tauri 可选组件；不装也能用核心 | 高 |
| 规则引擎 | 按工具/命令映射状态/台词 | 用户反复要求自定义映射 | JSON 规则，不执行任意代码 | 中 |
| 插件 SDK | 第三方扩展 | ≥2 个真实外部适配器 | 先 JSON 规则，再沙箱化插件 | 高 |
| 自建画廊 | 主题分发 | 本地导入率 > 5% 且有创作者投稿 | 优先接 Petdex API，不自建 | 高 |
| 自动更新 | 降低升级成本 | 安装基数足够大 | Sparkle/WinSparkle 或自研检查 | 中 |
| 签名/公证 | 消除 Gatekeeper 警告 | 有预算/证书，或安装失败集中在此 | Apple Developer ID + notarize | 中 |
| 匿名指标 | 补齐留存/失败数据 | 有明确指标缺口且 opt-in 方案通过审查 | 只统计功能使用，不含内容 | 中 |

> 这些方向都不是“永久不做”。唯一当前明确不做的是 **LLM 行为拦截**，见 §9。

## 5. Evidence plan

没有默认遥测。先用低成本、可解释的信号。

| 证据 | 方法 | 频率 | 用途 |
|---|---|---|---|
| 用户痛点 | 10 人访谈：5 个重度（每天 2+ 会话）、5 个普通 | M0 一次，之后每季度 | 排序 M1–M4 |
| Issue/评论 | 手动归类：安装、权限、多开、打扰、主题 | 每周 | 发现高频问题 |
| 安装失败 | 用户主动提供 `setup.log` / `doctor` 输出 | 持续 | M5 分发优先级 |
| 多开比例 | 访谈 + 可选本地诊断（只统计会话数） | M0 | M3 go/no-go |
| 权限响应 | 本地匿名计数（opt-in）或访谈 | M2 | 判断卡片是否值得 |
| 主题导入 | 本地计数（opt-in）+ issue | M4 | 判断画廊是否值得 |
| 留存 | 访谈 + Release 下载代理；不做默认遥测 | 每月 | 判断是否“每天开” |

**决策阈值**

- 多开用户 < 20% → 不做多会话聚合 UI。
- 权限事件 30 秒内被看到 < 80% → 优先修通知/聚焦，不急着做卡片。
- 一键脚本安装成功率 > 95% → 签名/打包后置。
- 主题导入 < 5% 活跃用户 → 停掉画廊计划。
- XP 实验无留存提升 → 删除，不进入主线。

**访谈脚本（最小版）**

1. 你一天开几个 Claude Code 会话？最长跑多久？
2. 最近一次“回来发现卡住”是什么情况？你当时在做什么？
3. 你希望桌宠在什么时候出现/消失？什么会让你想关掉它？
4. 你装的时候卡在哪一步？愿意为“免 Python”付多少时间/钱？
5. 你会换立绘/主题吗？从哪里找？

## 6. 指标

| 类型 | 指标 | 定义 | 目标 |
|---|---|---|---|
| 首要 | missed needs-input rate | 需要用户处理 > 5 分钟仍未确认的事件 / 总事件 | < 5% |
| 首要 | time-to-acknowledge | 从 `attention` 到用户点击/聚焦的中位/95 分位 | p50 < 30s，p95 < 2min |
| 次要 | 7 日仍开启 | 安装后第 7 天仍运行的设备/用户（opt-in 或访谈） | 基线 + 10% |
| 次要 | 安装成功率 | 首次安装后 24h 内看到桌宠的比例 | > 90%（M5），> 95%（v1.0） |
| 质量 | 权限误放行 | 未经用户明确 allow 的放行 | 0（硬门槛） |
| 质量 | 崩溃率 | 有 `pet-error.log` 的会话 / 总会话 | < 1% |
| 质量 | 打扰投诉 | “太吵/挡代码/分心”类 issue | 每版本 ≤ 2 |
| 性能 | 闲置 CPU / 内存 | Activity Monitor / `ps` | < 1% / < 120MB |
| 性能 | 权限 p95 | bridge 往返 + 卡片渲染（不含用户思考） | < 200ms |

**护栏**

- 不上传 prompt/命令/路径；匿名指标必须 opt-in 且可一键关闭。
- 不用“惩罚式”指标驱动设计。
- stars/下载量只做分发代理，不作为产品成功标准。

## 7. 质量与架构

架构不是“以后再说”，而是每个里程碑的完成门槛。详细约定见 [ARCHITECTURE.md](ARCHITECTURE.md)。

**四条底线**

1. **core 纯**：纯逻辑不 import 平台/UI/网络；`state_reader` / `settings` 只允许 stdlib 文件读写；平台差异在 adapter。
2. **一层契约**：状态、权限、主题、适配器四个边界；每个契约版本化、有 schema、有契约测试。
3. **薄入口 + 拒绝 god object**：`hooks/register.ts`、`pet_mac.py`、`pet.pyw` 只做组装；文件/函数有软上限，超限先拆。
4. **重构与功能分开**：边界不清时先重构；重构 PR 行为不变，测试先绿；新功能用 feature flag，默认关闭。

**完成定义**

每个功能必须通过 [ARCHITECTURE.md](ARCHITECTURE.md) §9 的 Definition of Done：模块边界、契约/迁移、失败路径、隐私、测试、文档、性能、回滚。架构门槛不通过，功能不算完成。

**增量重构**

先抽 `pet/core/`，再抽 `platform/`，最后拆 hooks/bridge；每一步独立 PR、行为不变。顺序见 [ARCHITECTURE.md](ARCHITECTURE.md) §6。

## 8. 安全、隐私、许可证底线

这些不是功能取舍，而是所有阶段都必须遵守的约束。

- **不持久化/不上传** prompt、回复正文、完整命令、密钥、URL 参数；权限卡片可在本机内存中展示完整命令，仅用于用户决策，不落盘、不联网。
- 状态文件只写项目名（basename）、文件名（basename）、短文案；隐私模式可隐藏。
- bridge 只绑 `127.0.0.1`，随机端口 + 每次运行随机 token；`bridge.json` `0600`；body ≤ 64KB；忙时直接回退，不排队。
- 权限默认 fail-open；**绝不自动 allow**；高风险命令二次确认；超时/异常一律 `ask`。
- 主题包不执行代码；校验路径穿越、zip bomb、超大文件；`license` 必填。
- 核心保持 MIT；AGPL 组件（如 Clawd）只借鉴产品思路，复用代码必须隔离为可选进程/独立仓库或取得授权。
- 第三方代码/素材进入仓库前记录到 `THIRD_PARTY_NOTICES.md`（v1.0 前建立）。
- 匿名指标默认关闭；只统计功能使用，不含内容；可一键关闭/清除。

## 9. 暂缓：LLM 行为拦截

**结论：当前不做。**

参考 `claude-code-tamagotchi` 的 violation detection：用 LLM 判断 Claude 是否“跑偏”，并在 PreToolUse 阶段阻断。想法有趣，但当前阶段风险大于收益：

- **误报**：把合法操作判成违规，打断用户工作流。
- **信任**：桌宠从“陪伴”变成“监工”，容易引起反感。
- **延迟/成本**：每次工具调用都要额外推理，增加延迟和费用。
- **责任**：错误阻断可能造成数据/时间损失。

**重新评估条件（全部满足才考虑）**

1. 核心 loop 稳定，且有真实用户主动要求。
2. 默认关闭，必须显式 opt-in。
3. 只做“提醒/建议”，不做自动阻断；阻断必须用户确认。
4. 可解释：告诉用户“为什么觉得跑偏”，并允许一键忽略/纠正。
5. 有可测量的精确率/召回率，误报率低于阈值。
6. 不读取/上传 prompt 内容；本地推理优先。

在此之前，用**规则型**提醒替代：例如“这条命令含 `rm -rf`”“这个会话已经跑了 2 小时，要不要休息”。规则型提醒可解释、可关闭、无 LLM 成本。

## 10. 版本映射

保持现有插件版本连续性，不承诺日期。

| 版本 | 对应里程碑 | 主题 |
|---|---|---|
| v0.2 | M1 | 核心 loop：生命周期、单实例、通知、doctor、隐私 |
| v0.3 | M2 | 权限注意力：通知 + 聚焦；条件性单请求卡片 |
| v0.4 | M3 + M4 | 多会话（条件）+ 陪伴/个性化/本地主题 |
| v0.5 | M5 | 分发：一键脚本、托盘、英文 README |
| v1.0 | 稳定化 | QA、性能、文档、迁移、发布 |

**维护边界**

| 范围 | 谁维护 | 承诺 |
|---|---|---|
| 核心、Claude Code 适配、macOS/Windows | 官方（你） | 随 Claude Code 版本更新；P0/P1 优先 |

| 3–5 个 Agent 适配 | 官方 + 社区 | 官方只保 1–2 个；其余标“社区支持” |
| 20+ Agent、工作台、画廊、插件 SDK | 社区/Explore | 不承诺；有维护者才启动 |
